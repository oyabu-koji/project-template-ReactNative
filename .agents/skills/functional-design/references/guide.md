# 機能設計ガイド

## 責務の分解

- Screen: 表示、利用者入力、アクセシビリティ。
- Component: 再利用可能な表示と局所的な操作。
- Hook / Controller: 状態遷移、非同期処理、画面とロジックの接続。
- Logic: ReactやExpoへ依存しない規則と計算。
- Service: Expo API、端末機能、永続化、外部I/O。

各要素について責務、入力、出力、依存先、失敗時の振る舞い、禁止事項を書く。

## データ契約

JavaScriptではJSDocまたは表を使い、型名、フィールド、必須性、許容値、初期値、制約を定義する。

```javascript
/**
 * @typedef {Object} Entity
 * @property {string} id
 * @property {string} label
 * @property {'idle' | 'active' | 'complete'} status
 */
```

## フローと状態

- 主な利用者フローを順序付き手順またはsequence diagramで示す。
- 状態ごとの入口、出口、遷移条件、無効入力を示す。
- 初期、空、読み込み、成功、失敗、再試行、利用不可を必要に応じて扱う。
- 非同期処理の重複実行、キャンセル、cleanupを定義する。

## テスト観点

- Logicの境界値・状態遷移をunit test候補にする。
- 主要な利用者操作と表示変化をcomponent test候補にする。
- 端末機能とレイアウトは必要に応じてシミュレータまたは実機で確認する。
- `package.json` に存在する品質scriptだけを実行候補にする。

## 完成チェック

- PRDの各P0要件が設計とテスト観点へ対応している。
- 画面と端末API、状態遷移と純粋ロジックの責務が混ざっていない。
- 正常系だけでなく失敗・再試行・無効入力が定義されている。
- 実装者が未決事項と確定事項を区別できる。
